# 任务 02：第一版（读、问、记闭环）

先读 `CLAUDE.md`；`docs/plan.md` 和 `docs/local.md` 存在时也读。任务 01 的技术验证已在测试平板上通过，本任务在它的代码上继续做，不推倒重来。

## 目标

读完一篇文档能留下笔记，并且不丢：

- 导入、阅读、恢复位置；
- 选中文字后划线、批注、侧栏问、发到 App、复制；
- 划线、批注、问答都挂在原文上，在笔记侧栏里按原文顺序查看；
- 导出成 md，整库备份与恢复。

## 范围

### 书架（最简文档列表）

- 一个列表页：标题、导入时间、最近阅读时间；点开即读；可以删除（二次确认，连同该文档的锚点、划线、批注、对话一起删）。
- 导入：文件选择器多选 md、粘贴文本导入、App 版从其他 App「用其他应用打开」（沿用任务 01 的实现）。
- 标题规则、同名保留两份并提示「已保留两份」，沿用任务 01。
- 任务 01 阅读页顶部的文档下拉框去掉，改由书架进入。内置测试文档保留在列表里，可以删除。

### 阅读

- 连续滚动。「点屏幕上下边缘翻一屏」作为设置里的开关，默认关闭。
- 目录抽屉：列出二、三级标题，点击跳转，高亮当前所在章节。
- 进度条：显示当前阅读百分比。
- **阅读位置恢复**：`documents.readingPosition` 存映射层里屏幕顶部第一个可见字符的位置。滚动时节流保存，切到后台（`visibilitychange`、`pagehide`）时立即保存。重新打开、切到其他 App 再回来、覆盖更新后，都回到原来的段落。
- 主题：日间、夜间，可以跟随系统。夜间时代码高亮、公式、划线颜色都要看得清。
- Obsidian 提示块（`> [!note]`、`> [!tip]`、`> [!warning]` 等）渲染成带标题的提示框；提示块里的文字照常可选、可划线。
- Mermaid 仍按普通代码块显示。

### 选中工具栏

按 `docs/plan.md` 的设计，五个按钮：

| 按钮 | 作用 |
| --- | --- |
| 划线 | 直接划线（单色，`color` 字段照常写入） |
| 批注 | 划线并打开输入框写一段文字 |
| 侧栏问 | 打开侧栏提问，选中内容自动带上 |
| 发到 App | 建待补充记录并调起分享（沿用任务 01） |
| 复制 | 复制原文，公式换回 TeX，附带文档名和章节 |

选区缓存、`pointerdown`、`visualViewport` 等规则沿用任务 01。点击已有划线时，可以查看 / 编辑批注、查看对话、删除划线。

### 侧栏问

- 在任务 01 的基础上补齐：
  - **上下文范围**：「本节」（默认）和「全文」可以切换。
  - **按 token 预算截取**：优先级依次是问题和选中原文（必须保留）、附近段落、本节其他内容、其他章节和历史对话。token 数用近似估算（中日韩字符按 1 个、其他按 4 个字符 1 个），预算在设置里可改，默认 8000 token。
  - 选了「全文」但放不下时，界面明确提示「全文过长，本次只发送了部分内容」。
- 回答里的任意一段都能「存为笔记」，挂到这段原文的锚点下面，存进 `notes` 表，`source` 为 `'ai'`。
- 整篇提问：不选文字时，也能从阅读页打开侧栏对整篇提问，对话的 `anchorId` 为空。

### 笔记侧栏

- 侧栏增加「笔记」页：本文的划线、批注、问答、待补充记录，按原文顺序排列，点一下跳回原文并闪一下。
- 待补充记录单独分组，阅读页显示未完成的数量（沿用任务 01）。
- 孤立的锚点（原文找不到了）放在最后一组「原文已找不到」，显示保存时的原文片段，数据不删。

### 导出 md

- 单篇导出，格式按 `docs/plan.md`「导出与备份」里的样例：YAML 信息、按章节组织、原文用引用块、下面接批注和问答，最后是「整篇提问」。
- 公式在导出里换回 TeX。
- 导出原文：把这篇文章本身（导入时的 md）导出，不含笔记。
- 入口：阅读页顶部「导出」可选「导出笔记」或「导出原文」；笔记侧栏里也有「导出 md」（导出笔记）；书架上每篇都有「导出」（导出原文）。
- App 版通过系统分享面板导出文件，网页版直接下载。

### 备份与恢复

- 一键导出 json：带格式版本号（`formatVersion: 1`），包含文档、锚点、划线、批注、对话和阅读设置。设置走白名单（`src/db/backup.ts` 的 `BACKUP_SETTINGS`），**API Key（`ai.key.*`）和 AI 接口配置（`ai.config.*`、`ai.provider`）都不进备份，也不从备份恢复**，否则恶意备份能改写接口地址，把本机的 Key 和文档发到别的服务器。
- 恢复时选「合并」或「替换」：
  - 合并：按 id 合并，同一个 id 已存在时保留本机的，不覆盖。
  - 替换：先完整读取并校验备份文件，校验通过后才清空本机数据再写入，整个过程放在一个事务里。
- 读取或校验失败时不动现有数据，并说明原因。
- 恢复后本机没有 Key 时，提示重新填写 AI 接口配置和 API Key。
- 设置页显示上次导出备份的时间，超过 7 天在阅读页提醒一次（每次超期只提醒一次）。
- 设置页提供「清除全部数据」：删除所有文档、锚点、划线、批注、对话和设置（包括 API Key），相当于重新安装；只保留诊断数据（启动计数器继续累加）。二次确认，确认框里提示上次备份时间。

### 网页版离线

- 用 vite-plugin-pwa 预缓存所有资源（含 KaTeX 字体和 Shiki 语言包），网页版断网后能打开并阅读已导入的文档。
- App 版资源本来就在本地，不注册 Service Worker。

### API Key 只写不读

保存后的 Key 在界面上不能再查看，只能更改或删除：

- 设置页对已保存的 Key 只显示「已设置」，不显示任何字符（包括末尾几位），没有「显示」按钮。
- 已保存的 Key 不回填到输入框里，页面 DOM 中不出现 Key 的内容。
- 「更改」：打开一个空的密码输入框，填新 Key 保存后覆盖旧的。
- 「删除」：二次确认后删除该服务商的 Key。
- Key 只在发请求时由 AI 客户端读取。诊断页、错误信息、日志、备份、导出里都不出现 Key（沿用任务 01 的遮挡规则）。
- 说明：这一条防的是在界面上被看到或被截图。Key 仍以明文存在本机 IndexedDB 里，靠安卓的应用沙箱隔离；做加密存储需要接安卓 Keystore，不在本任务范围。

### 其他

- 设置页：服务商（沿用任务 01）、上下文预算、主题、点边缘翻页开关、上次备份时间、备份与恢复入口。
- 诊断页保留，增加：阅读位置的保存次数和最近一次保存的值、Service Worker 状态。
- `README.md`：把「技术验证阶段」的说明改成第一版，补充导出和备份的说明。

## 不做

完整书架（进度、划线数、标签）、米黄主题和字号行距微调、文内搜索、Mermaid 渲染、四色划线、全局笔记页、疑问清单、批量提问、自定义快捷提问、文档改版后的划线迁移。

## 数据模型

沿用任务 01 的 Dexie schema 版本 1，本任务**预计不需要新版本**。如果实现中发现必须加字段或索引，按 `CLAUDE.md` 的规则新增版本号并写迁移，并在提交前说明。

- `notes` 新增可选字段 `source`：`'annotation'`（自己写的批注）或 `'ai'`（从 AI 回答里存的笔记）。不建索引，所以不需要新的 schema 版本；旧数据没有这个字段时按 `'annotation'` 处理。导出时分别显示为「批注」和「AI 回答摘录」。
- 新增设置项：`ai.contextBudget`（上下文预算，默认 8000 token）、`ui.theme`、`ui.edgeTap`、`backup.lastExportAt`、`backup.lastRemindedAt`。

## 单元测试（必须通过）

- 任务 01 已有的测试全部保留。
- 上下文组装：预算足够时各级内容都带上；预算不够时按优先级丢弃；问题和选中原文永远保留；「全文」被截断时返回截断标记。
- 导出 md：用测试文档加几条划线、批注、问答、待补充记录、整篇提问，输出与预期样例逐字一致；公式换回 TeX；孤立锚点的处理。
- 备份与恢复（用 fake-indexeddb）：
  - 导出再恢复到空数据库后，文档、锚点、划线、批注、对话、阅读位置全部一致；
  - 备份里没有任何 `ai.key.*`；
  - 合并时同 id 保留本机数据；
  - 文件损坏、版本号不认识、缺字段时报错，且原有数据完全不变。
- 阅读位置：位置 → 滚动目标的换算，以及文档内容变化后位置越界时的处理。
- API Key：读取设置页用的配置时不包含 Key，只有「是否已设置」；删除后发请求得到「还没填 API Key」。
- 提示块渲染：类型、标题、内容正确，文本映射层能正常拼出其中的文字。
